# Genio Institute (Apps Script web app)

Google Apps Script web app (HtmlService). `Code.gs` serves pages; each `Module*.html` is included into `Dashboard.html`. `Config.html` holds shared tokens, components, Supabase helpers, and the shared UI layer for popups/buttons. Deploy by importing files into Apps Script (`importProjectFilesFromDrive` in `Export.gs`), then create a new deployment version. Keep all element IDs and JS hooks intact when restyling. Product requirements and build status live in `docs/PRD.md` (v5); update its Section 14 status when a module changes.

## Design preferences (from the owner, apply to every page)

Reference implementations: `Login.html`, `ModuleHome.html`, `ModulePresensi.html`.

- **Fonts:** Plus Jakarta Sans everywhere (`var(--font)`). Poppins only for the brand name "Genio Institute" (`var(--font-brand)`, class `.genio-brand-title`). Never use Poppins elsewhere.
- **Logo:** keep the original lockup: logo image badge + "Genio" (blue) "Institute" (red) + "Yogyakarta". Do not replace it with a wordmark.
- **Type scale:** small and airy, like the Claude app. Body 11.5-12.5px, labels 10-11px, section titles 12px, card names 12-13px, hero numbers ~20px (18px in flat desktop rows).
- **Weights:** light by default (400-500), but use bold where it helps scanning: key numbers and money values 700, section titles / names / greetings / primary buttons 600, page titles 700.
- **Highlight panels:** dark blue gradient (`linear-gradient(135deg, #070833 0%, #101075 55%, var(--blue) 100%)`), radius 18px, one hero number made large and bold (28-34px, 800) so it stands out, plus a meaningful ornament drawn from real data (Home: 6-month omset sparkline + margin bar; Presensi: weekly bar chart, amber weeks = late). Split layout: main area left, translucent side panel (`rgba(255,255,255,.06)`) right; stack on mobile. Mint `#7CF0C3` for positive, amber `#FFC46B` for late, coral `#FF9C94` for costs. Must wrap safely (`minmax(0,1fr)`, `min-width:0`, ellipsis on secondary text) so long values never overlap.
- **Charts & data entry animation:** single-hue blue charts, smooth monotone curves (never overshoot data), recessive grid, hover crosshair + tooltip, previous-period ghost line (dashed grey) when data exists, no dual-axis charts. When data appears: numbers count up (`homeRevealValue`), lines draw left-to-right, bars grow with a small stagger, list rows fade/slide in. Always honor `prefers-reduced-motion`. Indonesian number format ("Rp 3,4 Jt").
- **Shapes:** buttons/inputs 8-10px radius, cards 14px, popups 18px, 1px borders `var(--border)`.
- **Buttons:** primary = blue background, white text; secondary = white with border. No black (`var(--ink)`) buttons.
- **Popups:** follow the login form style: light title, labels above grey input boxes (`var(--surface)`), blue focus ring, 36px actions. Handled globally by the "Genio UI layer" in `Config.html`. Every popup must be a `.modal-overlay` so the shared keyboard handler in `Config.html` (`genioKeyboardAware`) moves it to the top half of the screen while a text field is focused on touch devices; do not add popups outside `.modal-overlay` that contain text inputs.
- **Roles:** `Dashboard.html` sets `role-<role>` on `<body>` and filters the dock (`PRIMARY_TABS`) and Lainnya menu (`ROLE_MENU`) per role. Kepala unit: dock Home/Presensi/Jadwal/Lainnya. HRD: dock Home/Tutor/Jadwal/Lainnya, Presensi read-only in Lainnya. Both use `ModuleHomeUnit.html` (panel `home-unit`) as Home; it switches to HRD mode (all units, SDM highlight and metrics) when the role is hrd. Tutor: dock Beranda/Presensi/Gaji/Profil with no Lainnya; `showModule` maps tutor tabs to their own panels (`home-tutor` in `ModuleHomeTutor.html`, `presensi-tutor` in `ModulePresensiTutor.html`, `gaji-tutor` in `ModuleGajiTutor.html`, `profile-detail`). Hide buttons a role may not use with `.role-<role>` CSS rules in `Config.html`, lock unit pickers with `genioScopeUnits()`, and read `unit_id`/`unit_nama` from the session (`genioEnsureSessionProfile()`). RLS is the real guard; UI hiding only avoids actions that would fail.
- **Tutor + button:** tutors get an "Isi presensi" action from `Dashboard.html` on every page: a round blue button with a white stroke in the middle of the bottom bar on phones (a gap slot `.dock-fab-gap` keeps the tabs apart), and a floating white pill with the round button on the left at the bottom right on desktop. Both open the session picker via `window.genioPresensiTutor.open({action:'pick'})` and fade out while a `.modal-overlay.show` is open. Do not add another "Isi presensi" button to the highlights. Dock and tab backgrounds are fully rounded (999px) on phone and desktop, and the bottom bar is compact (max 350px).
- **Icon map (Phosphor, one icon per concept everywhere: dock, Lainnya menu, module headers, Home tiles, quick add menu):** presensi `check-circle`, siswa `student`, kontrak `file-text`, jadwal `calendar-blank` (a held session or pertemuan uses `calendar-check`), operasional `receipt`, tagihan `credit-card`, tutor `chalkboard-teacher`, paket belajar `books`, unit `buildings`, user `user-gear`, news `newspaper`, pengaturan `gear`, gaji `wallet`, beranda `house`, profil `user-circle`. Do not use parcel/box icons for paket belajar. New modules must reuse this map or add to it here.
- **Quick add button (+):** `Dashboard.html` adds a round + in the middle of the bottom bar on phones and a floating white pill with the + on the left at the bottom right on desktop. Manajer and super admin have no + button. Tutor: one tap goes straight to the fill-in-attendance flow (no menu). Kepala unit (presensi, siswa, operasional, kontrak, jadwal) and HRD (tutor, siswa, kontrak, jadwal): a half-circle wheel of white sectors opens from behind the bottom bar on phones (icons and labels in blue), and a white card list "Tambah baru" opens above the pill on desktop. Each item opens the module and presses its add button (`ps-openWakilBtn`, `os-addBtn`, `ops-addBtn`, `ktr-addBtn`, `jdw-addBtn`, `dt-pendaftaranToggle`, `pkt-addBtn`), so keep those IDs.
- **User avatars:** always render people with `genioAvatarInner(nama, foto_profil_url, initials)` / `genioSetAvatar(el, ...)` from `Config.html` (photo when uploaded, initials otherwise or when the image fails). Include `foto_profil_url` in the `users` embed of the query.
- **Card or table view:** every list with a card/table toggle starts as cards on phones (< 768px) and as a table on tablets and desktop, for all roles. Read and save the choice with `genioViewPref(key, cardVal)` / `genioSaveViewPref(key, val)` from `Config.html` (stored separately for phone and wide screens); do not read `localStorage` directly.
- **Search boxes:** every text input whose placeholder starts with "Cari" (or `type="search"`) gets a round x button automatically from `Config.html` (`genioSearchClear`, also for inputs created later). It clears the value and fires `input`, so keep filtering on the `input` event. Do not add your own clear buttons.
- **Tab bars:** segmented tabs and docks can be held and dragged like the manager dock: bind them with `genioBindScrub(bar, opts)` from `Config.html`. Re-render lists on tab/filter/view switches inside `genioKeepScroll(listEl, fn)` so the page does not jump to the top.
- **Tables:** freeze the identifying columns on the left so they stay put when the table scrolls sideways (`position:sticky`, fixed widths, `border-collapse:separate`, solid background on sticky cells). Kontrak: No + Siswa. Jadwal: No + Tutor. Presensi: No + Tanggal + Tutor. Gaji: No + Nama tutor. Operasional: No + Transaksi. Kelola unit: No + Unit. Paket belajar: No + Nama paket. Kelola user: No + Nama. Frozen columns must be adjacent and first, so reorder columns if needed. Always plan for mobile: on narrow screens slim the frozen columns (hide avatars, drop the year, ellipsis with a `title` tooltip) so other columns stay visible. Size columns to content and avoid fixed `min-width` on the table, so it fits without scrolling when the screen is wide enough.
- **Table pagination:** every data table gets a footer automatically from `Config.html` (`genioPager`): info "Menampilkan 11-20 dari 87 data", rows per page (10/25/50/100, default 25 on wide screens and 10 on phones, saved separately), first/previous/page numbers/next/last buttons. It hides rows outside the page in the browser, so keep rendering all rows with a running "No" column. New tables must use the card > wrap > table structure and one of the registered table classes (`dt-table`, `gj-table`, `gt-table`, `jdw-table`, `kp-table`, `ku-table`, `ktr-table`, `ops-table`, `os-table`, `pkt-table`, `ps-table`, `tg-table`); add new classes to `TABLES` in `genioPager`. `scrollIntoView` on a hidden row opens its page automatically. Do not build your own pager.
- **Weekly schedule dots:** the dots in every weekly schedule grid (Home manajer, Home kepala unit/HRD/tutor, Jadwal, Presensi tutor) are 6px with a 1.5px white ring; status rings (late/done) add a 1.25px colored ring. Tapping one zooms it by about 1.45x (`.is-picked` in `Config.html`), so keep them small and keep the invisible hit area (`::after` inset -7px).
- **Copy:** sentence case, no em dashes, no uppercase micro-labels.
- Light theme only (whole app is light).

## Database (Supabase)

- Project **GDIY** (ref `lmtockvqirnqjabdhxbh`, region ap-southeast-1). This is the live database; ask before any write, migration, or delete. Other projects in the account ("Manajemen Genio DIY", "genio-get") are inactive and unused.
- Schema check (27 Sep 2026): all 123 `supaRest` calls in the code match the tables and columns; all 16 public tables have RLS enabled.
- Edge Function `admin-users` (source in `supabase/functions/admin-users/index.ts`, deployed with verify_jwt off because it checks the caller token itself): creates accounts (Auth + `public.users` + `tutor_profile`), deletes accounts including the Auth user, and changes a user's login email (`update_email`: Auth + `public.users` together, no verification email). Only manajer/super_admin (any role) and HRD (tutors only) can change emails; users cannot change their own email in Profil. Manajer/super_admin manage all roles (super_admin only by super_admin), HRD only tutors. Called from the browser via `genioAdminUsers()` in `Config.html`. Redeploy after editing the source.
- Trigger `presensi_before_write` guards tutor writes (source of record in `supabase/migrations/20260927_presensi_tutor_write_guard.sql`): tutor inserts and revisions are always forced to `pending` with server-set unit and input time; revisions may change only tanggal, jam, materi, foto; a late row stays late. `terlambat` is recomputed only when tanggal/jam change, so approval keeps it.
- Open security advisor warnings, noted and deliberately left as is for now:
  1. SECURITY DEFINER helpers callable by signed-in users via RPC: `current_role_name`, `current_status`, `current_unit_id`, `is_manajemen`, `is_staff_lintas_unit`. They are used by RLS policies, so do not revoke EXECUTE without testing the policies first.
  2. Leaked password protection is disabled (Supabase dashboard, Authentication settings; no code change needed).
